## Модуль 1: Python для ML & Высокопроизводительные вычисления

### 1.1 Как устроен GIL (Global Interpreter Lock) в CPython и как его обходят в ML?
* **Суть:** GIL — это мьютекс, предотвращающий одновременное выполнение нескольких нативных потоков байт-кода Python внутри одного процесса. Это сделано для потокобезопасности управления памятью через подсчет ссылок (`reference counting`).
* **Влияние на ML:** Ограничивает CPU-bound многопоточность (`threading`). 
* **Обход:**
  * Использование многопроцессорности (`multiprocessing`), где у каждого процесса свой интерполятор и адресное пространство.
  * Вынос вычислений в C/C++/CUDA расширения (NumPy, PyTorch, SciPy отпускают GIL во время выполнения тяжелых тензорных операций `Py_BEGIN_ALLOW_THREADS`).

### 1.2 В чем разница между `deepcopy`, `copy` и представлением (`view`)?
* **`copy.copy()` (Shallow copy):** Создает новый составной объект, но вставляет в него ссылки на объекты оригинала.
* **`copy.deepcopy()`:** Рекурсивно создает дубликаты всех вложенных объектов.
* **`view` (в NumPy/PyTorch):** Не копирует данные в памяти. Создает новый заголовок массива/тензора с другими `strides` и `shape`, указывающий на тот же буфер в RAM/VRAM. Изменение данных во view меняет оригинальный массив.

### 1.3 Как работают генераторы (`yield`) и почему они критичны для работы с данными?
* **Суть:** Генератор — это функция, возвращающая итератор с ленивым вычислением (`lazy evaluation`). Состояние локальных переменных замораживается между вызовами `next()`.
* **Применение в ML:** Позволяет потоково обрабатывать датасеты, не помещающиеся в оперативную память (out-of-core processing), например, чтение терабайтных логов или парсинг корпусов текстов построчно с константной сложностью по памяти $O(1)$.

### 1.4 Векторизация в NumPy vs списки Python
* Списки Python хранят массив указателей на объекты `PyObject` (накладные расходы памяти, кэш-промахи процессора, динамическая диспетчеризация типов).
* `np.ndarray` хранит непрерывный блок памяти с фиксированным типом данных (C-contiguous или Fortran-contiguous). Векторизованные операции транслируются в SIMD-инструкции процессора (AVX-512, NEON) и оптимизированные библиотеки BLAS/LAPACK.

## Модуль 2: PyTorch & Архитектура Deep Learning

### 2.1 Как работает Autograd и вычислительный граф в PyTorch?
* PyTorch строит **динамический граф вычислений** (Define-by-Run) во время прямого прохода (`forward pass`).
* У каждого тензора, для которого `requires_grad=True`, есть атрибут `grad_fn`, указывающий на операцию, создавшую этот тензор.
* При вызове `loss.backward()` запускается обратный проход (`reverse-mode automatic differentiation`), вычисляющий частные производные по правилу цепочки (Chain Rule) от листьев графа к корню, аккумулируя значения в атрибут `.grad`.

### 2.2 В чем разница между `model.eval()`, `torch.no_grad()` и `torch.inference_mode()`?
* **`model.eval()`:** Переключает режим работы модулей (например, отключает рандомизацию в `Dropout`, переводит `BatchNorm` на использование накопленных скользящих средних `running_mean` и `running_var` вместо батчевой статистики). **Не отключает** вычисление градиентов.
* **`with torch.no_grad()`:** Контекстный менеджер, отключающий трекинг градиентов для экономии памяти, но сохраняющий метаданные для версионирования тензоров.
* **`with torch.inference_mode()`:** Более строгая и быстрая версия `no_grad()`. Полностью отключает отслеживание версий тензоров, обеспечивая максимальную производительность при инференсе.

### 2.3 Почему возникает утечка памяти на GPU (`CUDA Out of Memory`) при обучении?
* **Типичные причины:**
  1. Аккумуляция потерь через `total_loss += loss` вместо `total_loss += loss.item()` (тянет за собой весь граф вычислений за все эпохи).
  2. Разрастание графа при сохранении промежуточных тензоров с градиентами в глобальные списки.
  3. Фрагментация памяти кэшера PyTorch (лечится вызовом `torch.cuda.empty_cache()` или настройкой `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`).
  4. Слишком большой размер батча или отсутствие Gradient Accumulation / Mixed Precision (`torch.amp.autocast`).

### 2.4 Настройка `DataLoader`: `num_workers`, `pin_memory`, `persistent_workers`
* `num_workers`: Задает количество фоновых процессов CPU для предзагрузки и аугментации данных.
* `pin_memory=True`: Выделяет память в специальной page-locked (pinned) области оперативной памяти, что позволяет видеокарте считывать данные через DMA (Direct Memory Access) без участия процессора, ускоряя transfer `host-to-device`.
* `persistent_workers=True`: Предотвращает пересоздание пула воркеров на каждой эпохе, экономя время на инициализации.

## Модуль 3: Классическое машинное обучение (Classical ML)

### 3.1 Bias-Variance Tradeoff (Компромисс смещения и дисперсии)
Общая ошибка модели на тесте раскладывается на три компонента:
$$\text{Error} = \text{Bias}^2 + \text{Variance} + \sigma^2$$
* **Смещение (Bias):** Ошибка упрощения предположений алгоритма (высокий Bias $\to$ недообучение / Underfitting).
* **Дисперсия (Variance):** Чувствительность алгоритма к малейшим флуктуациям обучающей выборки (высокая Variance $\to$ переобучение / Overfitting).
* **Неустранимая ошибка ($\sigma^2$):** Шум в самих данных.

### 3.2 Регуляризация: $L_1$ (Lasso) vs $L_2$ (Ridge)
* **$L_1$-регуляризация ($\lambda \sum |w_i|$):** Приводит к занулению весов (разреженные матрицы весов). Выполняет отбор признаков (Feature Selection) за счет ромбовидных контуров ограничений в оптимизационном пространстве.
* **$L_2$-регуляризация ($\lambda \sum w_i^2$):** Уменьшает абсолютные значения весов к нулю, но редко делает их строго нулевыми. Эффективно борется с мультиколлинеарностью.

### 3.3 Деревья решений и критерии разбиения (Gini vs Entropy)
* **Gini Impurity:** $I_G(p) = 1 - \sum_{i=1}^J p_i^2$ (вычисляется быстрее, так как не содержит логарифмов).
* **Entropy:** $H(p) = -\sum_{i=1}^J p_i \log_2(p_i)$ (информационный выигрыш Information Gain).
* На практике разница в качестве моделей составляет $<1\%$, однако Gini предпочтительнее с точки зрения вычислительной эффективности.

### 3.4 Случайный лес (Random Forest) vs Градиентный бустинг (XGBoost/LightGBM/CatBoost)
| Параметр | Random Forest | Gradient Boosting |
| :--- | :--- | :--- |
| **Парадигма** | Bagging (параллельное обучение независимых глубоких деревьев) | Boosting (последовательное обучение неглубоких деревьев) |
| **Цель** | Снижение Variance при сохранении низкого Bias | Снижение Bias за счет шага по антиградиенту функции потерь |
| **Оверфиттинг** | Устойчив к переобучению при росте числа деревьев | Склонен к переобучению при чрезмерном числе итераций |
| **Сложность** | Легко масштабируется горизонтально | Требует аккуратного подбора Learning Rate и регуляризаций |

## Модуль 4: NLP, LLM & RAG Pipeline

### 4.1 Архитектура Трансформера: Self-Attention
Формула Scaled Dot-Product Attention:
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
* Масштабирующий коэффициент $\sqrt{d_k}$ стабилизирует градиенты, предотвращая попадание значений скалярных произведений в зоны насыщения функции softmax при больших размерностях векторов.

### 4.2 Стратегии чанкинга (Chunking Strategies)
* **Fixed-size Chunking:** Разбиение по фиксированному числу токенов со скользящим окном (overlap $10-20\%$).
* **Recursive Character Chunking:** Разбиение по иерархии разделителей (`\n\n` $\to$ `\n` $\to$ ` ` $\to$ `""`), сохраняющее абзацы и параграфы.
* **Semantic Chunking:** Расчет косинусного расстояния между эмбеддингами последовательных предложений. Точка разреза ставится там, где семантическая разница превышает заданный перцентиль (порог смены темы).
* **Agentic/Document-aware Chunking:** Парсинг с учетом разметки документа (Markdown заголовки, таблицы, теги HTML, JSON-структуры).

### 4.3 Преобразование запросов: HyDE, Multi-Query, Step-Back
* **HyDE (Hypothetical Document Embeddings):** LLM генерирует гипотетический ответ на вопрос пользователя. Эмбеддинг этого ответа используется для поиска по базе. Решает проблему семантического разрыва (asymmetric search: короткий вопрос $\leftrightarrow$ длинный пассаж).
* **Multi-Query:** LLM генерирует $N$ синонимичных перефразировок исходного запроса. Результаты векторного поиска агрегируются и дедуплицируются.
* **Step-Back Prompting:** LLM формулирует более общий, высокоуровневый вопрос для извлечения базовых концепций и контекста предметной области.

### 4.4 Векторный поиск: HNSW vs IVF
* **IVF (Inverted File Index):** Пространство делится на кластеры с помощью Voronoi cells ($k$-means). При поиске сканируются только центроиды, ближайшие к вектору запроса, и векторы внутри выбранных кластеров.
* **HNSW (Hierarchical Navigable Small World):** Многоуровневый граф с концепцией "Skip-list". Верхние уровни содержат длинные связи для быстрой навигации, нижние — плотные локальные связи. Обеспечивает лучший компромисс Recall/Latency за счет большего потребления RAM.

### 4.5 Двухэтапный поиск: Bi-Encoder vs Cross-Encoder (Re-ranking)
* **Bi-Encoder (Retrieval):** Независимо кодирует запрос и документы в векторы: $\text{sim} = \cos(E(q), E(d))$. Быстро ($O(1)$ поиск в векторной БД через ANN), но теряет глубокие перекрестные взаимодействия слов.
* **Cross-Encoder (Re-ranking):** Принимает пару $\text{[CLS]} + q + \text{[SEP]} + d + \text{[SEP]}$ и пропускает через все слои внимания трансформера одновременно. Высочайшая точность, но вычислительно тяжело.
* **Паттерн:** База данных отбирает топ-100 кандидатов через Bi-Encoder $\to$ Re-ranker (Cohere, BGE-Reranker) фильтрует и упорядочивает их до топ-3/5 для контекста LLM.

### 4.6 Метрики оценки RAG (RAG Triad & RAGAS)
1. **Faithfulness (Достоверность):** Доля утверждений в финальном ответе, которые можно логически вывести из переданного контекста (детектор галлюцинаций).
2. **Answer Relevance (Релевантность ответа):** Насколько сгенерированный ответ точно отвечает на заданный вопрос (штрафует за уход от темы).
3. **Context Precision (Точность контекста):** Отношение релевантных чанков к общему числу извлеченных чанков с учетом их ранга (релевантные фрагменты должны быть вверху).
4. **Context Recall (Полнота контекста):** Содержит ли найденный контекст всю информацию, необходимую для формирования эталонного ответа (Ground Truth).

## Модуль 5: ML System Design, Оптимизация & Деплой

### 5.1 Квантование LLM: Post-Training Quantization (PTQ)
* Перевод весов и активаций из FP16/BF16 в форматы пониженной разрядности:
  * **INT8 / FP8:** Минимальная потеря качества, ускорение вычислений на Tensor Cores.
  * **INT4 (AWQ, GPTQ):** AWQ (Activation-aware Weight Quantization) сохраняет в высокой точности $1\%$ наиболее важных весов (определяемых по амплитуде активаций), квантуя остальные до 4 бит. Сокращает VRAM в 3-4 раза.
  * **GGUF (llama.cpp):** Оптимизировано для инференса на CPU и Apple Silicon через mmap.

### 5.2 Оптимизации инференса: PagedAttention и vLLM
* Стандартный механизм генерации кеширует ключи и значения (KV-Cache) для предыдущих токенов в непрерывных блоках VRAM, что приводит к фрагментации до $60-80\%$ памяти.
* **PagedAttention:** Применяет виртуальную память с подкачкой страниц (как в операционных системах) к KV-Cache. Память выделяется неконсистентными фиксированными блоками, что позволяет динамически масштабировать батчинг (Continuous Batching) и увеличивать пропускную способность (`throughput`) сервера в 5-10 раз.

### 5.3 Data Drift vs Concept Drift
* **Data Drift (Covariate Shift):** Изменение распределения входных признаков $P(X)$ при неизменном распределении целевой переменной $P(Y|X)$. Пример: пользователи стали загружать фотографии более высокого разрешения.
* **Concept Drift:** Изменение зависимости между входом и целевой переменной $P(Y|X)$. Пример: изменение покупательского поведения во время экономического кризиса.
* **Методы отслеживания:** Расстояние Вассерштейна, дивергенция Кульбака-Лейблера (KL), тест Колмогорова-Смирнова (KS-test), Population Stability Index (PSI).
